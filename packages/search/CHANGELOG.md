# Changelog

## 0.1.5 → 0.2.0, in full

Every other section of this file is generated by release-please from
Conventional Commit subjects, which means it lists only `feat`, `fix`, `perf`,
`refactor`, `build` and `deps` work — `chore`, `docs`, `ci` and `test` are
deliberately hidden. This section is written by hand because almost all of
0.1.5 → 0.2.0 was committed as `chore`, and a generated changelog for it says
close to nothing.

`0.2.0` is the first release in roughly eighteen months and the first cut by
release-please. The generated `0.2.0` entry names five commits; the real change
is this.

**The ripgrep fork is gone.** This package used to depend on the `grep`
meta-crate from a fork, `dgopsq/ripgrep` at tag `13.0.0-wasm`, which existed
only to swap `std::time` for the `instant` crate in `grep-printer`, `ignore`
and the CLI core — `Instant::now()` has no clock on `wasm32-unknown-unknown`.
None of those crates were ever used here; they arrived because the meta-crate
pulled them in. Depending on `grep-matcher`, `grep-regex` and `grep-searcher`
directly, straight from crates.io, means they are never compiled and the
problem the fork solved no longer exists. `Cargo.lock` lost 21 crates.

**That fix was not free of consequences, and one of them was a bug fix nobody
asked for.** `^` used to anchor to the network chunk rather than the line.
Modernizing the dependencies fixed it upstream with no change to `lib.rs`, and
the only thing that noticed was a test written to assert the broken behaviour.

**⚠️ Breaking: the build target changed from `bundler` to `web`.** `await
init()` is now required before calling `search_bytes`. Consumers of
`@netgrep/netgrep` are unaffected — the wrapper absorbs instantiation
internally — but anyone importing this package directly must add it.

**wasm-bindgen 0.2.82 → 0.2.126**, and the Rust toolchain is now pinned to
1.97.1 in `rust-toolchain.toml` rather than tracking `stable`, which is how an
unrelated Rust release once broke the build with no commit to point at.

**`wee_alloc` was removed**, and the assumption behind it was wrong: it was
worth 6,839 bytes, 0.6%, because modern `rustc` closed the gap. The same
measurement turned up something larger — `[profile.release]` had been sitting
in `packages/search/Cargo.toml`, where Cargo ignores it and only warns. Every
release build since the beginning had been made at the default opt-level with
no LTO. Moving it to the workspace root took 155,469 bytes off the binary;
`codegen-units = 1` and `panic = 'abort'` took another 76,166.

**Net, the `.wasm` grew 12.1%** — 1,038,608 → 1,164,691 bytes. Newer
`regex-automata` carries larger DFA and Unicode tables, and the profile fix and
the size tuning together recover most but not all of it.

**Two API-visible changes** are in the generated entry above but worth naming
here: each pattern is now compiled once and shared through a memo, which also
made an invalid pattern a catchable error rather than a panic; and
`search_bytes_line` was added, returning the first matching line when the caller
asks for it.

**Tests no longer need a browser.** `tests/search.rs` was a `wasm-bindgen-test`
suite driven through wasm-pack and ChromeDriver, which downloaded the newest
driver, could not drive an older local Chrome, and overrode `CHROMEDRIVER` so
the mismatch could not be fixed by hand. It is now a plain native `cargo test`;
browser coverage moved to the TypeScript integration suite under Playwright.
