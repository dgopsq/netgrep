## 0.1.5 → 0.2.0, in full

Every other section of this file is generated by release-please from
Conventional Commit subjects, which means it lists only `feat`, `fix`, `perf`,
`refactor`, `build` and `deps` work — `chore`, `docs`, `ci` and `test` are
deliberately hidden. This section is written by hand because much of
0.1.5 → 0.2.0 was committed as `chore`, and a generated changelog understates
it badly.

`0.2.0` is the first release in roughly eighteen months and the first cut by
release-please. **If you are on `0.1.5`, you are running a version with three
correctness defects that are fixed here**, and that is the main reason to
upgrade.

**Matches that straddled a chunk boundary were missed.** A pattern split across
two network chunks — which is to say, an ordinary pattern in an ordinary file,
decided by where the network happened to break — simply did not match. It is
fixed by retaining the incomplete trailing *line* rather than a byte window, so
what the engine is handed is now a block of complete lines. One caveat remains
and is deliberate: inside a single line longer than 64 KB the retained tail
degrades back to a byte window, so a match longer than 64 KB is still lost and
`^` can still match at the window's first byte. Prose does not reach that.

**A partial result could poison the cache.** Resolving early — the whole point
of searching while downloading — left a truncated body in the cache, and the
next search of the same URL was answered from it. The two defects had to be
fixed together: the boundary bug had been *suppressing* early resolution, so
closing it alone would have made the cache bug fire more often, in the default
configuration.

**Concurrent searches of one URL downloaded it twice.** A per-URL in-flight
registry now shares one download between them. This applies only to instances
running with the cache **on**, since the cache entry is what the second caller
is handed; with the cache off both callers still fetch, which is deliberate and
pinned by a test.

**New: the first matching line, on request.** `captureLine` makes a result carry
the matching line as well as the boolean. The API is otherwise unchanged and
stays deliberately small — no line numbers, no byte offsets, no match counts, no
all-matches, no context lines, no ranking. Each of those has been considered and
refused.

**The public API is otherwise the same.** `@netgrep/search` 0.2.0 requires
`await init()` before `search_bytes`, but this package absorbs that internally,
so nothing changes for consumers of the wrapper.

**Underneath**, the repository moved from Nx and yarn to pnpm workspaces, from
Jest to Vitest, from ESLint/Prettier to Biome, and the browser suite from
wasm-pack's ChromeDriver harness to Playwright's own pinned Chromium. None of
that is visible in the published package beyond the fixes above.
