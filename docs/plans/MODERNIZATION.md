# Modernization plan

**Status:** Agreed 2026-07-28. Not yet started.
**Goal:** a repository that builds, lints and tests green on a current toolchain.
**Explicit non-goal:** shipping anything to npm. See [Decision 1](#1-the-finish-line-is-green-ci-not-a-release).

This document is the durable record of a design conversation. It exists so that the *reasoning* behind the
fourteen decisions below survives — an agent resuming at PR 3 should not have to re-derive why pnpm, why the
grep sub-crates, why no dependency bot.

Every version number here was verified against the live registries on **2026-07-28**. Every claim about the
repository was verified by reading it. The one non-obvious technical claim — that the ripgrep fork is
droppable — was verified by building it; see [Appendix A](#appendix-a-the-fork-removal-probe).

## The gap

| | in repo | current | note |
|---|---|---|---|
| Nx / `@nrwl/*` | 14.5.4 | 23.1.0, `@nx/*` | 9 majors **and** a package-scope rename |
| `@nxrs/cargo` | 0.3.3 | 0.6.2 | third-party, no release since 2024-05 |
| TypeScript | 4.7 | 7.0.2 | `latest` is now the Go rewrite |
| ESLint | 8.15 | 10.8.0 | flat config |
| jest / ts-jest | 29 / 28 | 30 / 29 | mismatched *today*; ts-jest warns every run |
| Node | 18.7.0 | 24.x LTS "Krypton" | 18 is end-of-life |
| `wasm-bindgen` | 0.2.82 | 0.2.126 | caps Rust at ≤ 1.81 |
| Rust | `channel = "stable"` | 1.97.1 | unpinned — **this is why CI is red** |
| `wee_alloc` | 0.4.5 | 0.4.5 | untouched since 2019-08 |
| `grep` | git fork of 13.0.0 | sub-crates on crates.io | fork is removable |

For scale, the thing being modernized is **380 lines of TypeScript** (of which 172 are tests) and **48 lines
of Rust**. Most of the weight in this plan is configuration, not code.

## Decisions

### 1. The finish line is green CI, not a release

Everything builds, lints and tests on a current toolchain. **Nothing is republished** — npm keeps serving
`@netgrep/netgrep@0.1.5` and `@netgrep/search@0.1.5` throughout.

*Consequence, stated plainly:* the correctness bugs stay shipped. Users of 0.1.5 keep hitting the
chunk-boundary false negative. That is an accepted, deliberate outcome of this scope, not an oversight.

*Consequence:* consumer-facing ergonomics (an `exports` map, revisiting the wasm-pack target so consumers
don't need `experiments.asyncWebAssembly`) are **out of scope**. They only pay off on release.

*This supersedes the "maintenance only, no feature work" stance* in `AGENTS.md` and `docs/BACKLOG.md`, written
earlier the same day. Those documents are rewritten in PR 5.

### 2. Nx is removed, not upgraded

Nx 14.5.4 is nine majors and a scope rename behind. It is not earning that migration here:

- CI never runs `nx affected` — only `run-many --target=lint` and `--target=test`. The dependency graph and
  remote cache, Nx's actual differentiators, are unused.
- Three packages, ~450 lines of source. The task graph is a straight line.
- What Nx wraps: `@nrwl/js:tsc` (a `tsc` invocation that also synthesizes `dist/package.json`),
  `@nrwl/linter:eslint`, `@nrwl/jest:jest`, `@nxrs/cargo:clippy`, and two `nx:run-commands` passthroughs
  that already shell straight out to `wasm-pack`.

Removing it deletes **nine packages** in one move: `@nrwl/cli`, `@nrwl/eslint-plugin-nx`, `@nrwl/jest`,
`@nrwl/js`, `@nrwl/linter`, `@nrwl/web`, `@nrwl/workspace`, `nx`, `@nxrs/cargo` — and with them the bulk of
the 163 Dependabot alerts on `main`, which are overwhelmingly transitive dev dependencies of that tree.

*The one real cost:* `@nrwl/js:tsc` synthesizes `packages/netgrep/dist/package.json`, including the `tslib`
peer dependency. That manifest must now be hand-written and correct.

### 3. pnpm workspaces

Replaces yarn 1.22 classic and collapses **three** lockfiles (root, `packages/netgrep`, `packages/example`)
into one. Also sidesteps a live environment problem: the global `~/.yarnrc` on this machine has a stale
`yarn-path` pointing at a deleted binary, and every yarn invocation so far has needed `YARN_IGNORE_PATH=1`.

pnpm's strictness about phantom dependencies is a genuine fit — undeclared transitive imports are precisely
the class of rot this repo accumulated.

### 4. `@netgrep/search` gets a hand-written wrapper manifest

The problem: the publishable `@netgrep/search` package is not `packages/search/` — it is
`packages/search/pkg/`, a **gitignored directory generated by wasm-pack**. A workspace glob cannot point at a
build output that does not exist on a fresh clone.

The fix — a checked-in `packages/search/package.json` that owns the name, with wasm-pack's output demoted to
an internal artifact:

```jsonc
{
  "name": "@netgrep/search",
  "version": "0.1.5",        // synced from Cargo.toml by scripts/post_build.js
  "type": "module",
  "main": "pkg/index.js",
  "types": "pkg/index.d.ts",
  "files": ["pkg"]
}
```

`pnpm-workspace.yaml` then globs plain `packages/*`, and `packages/netgrep` declares
`"@netgrep/search": "workspace:*"`.

Fresh-clone behaviour, which is the point of choosing this shape:

| | works without Rust installed? |
|---|---|
| `pnpm install` | yes |
| `pnpm test` (unit, `@netgrep/search` mocked) | yes |
| `pnpm test` (integration) / `pnpm build` | no — needs `wasm-pack build` first |

So a contributor touching only TypeScript never has to install a Rust toolchain. The rejected alternative —
globbing `packages/search/pkg` directly — would have forced exactly that.

**This is what finally fixes the repository's headline gotcha** (`AGENTS.md` §2): local Rust edits currently
reach neither the TypeScript package nor the example, because root `package.json` depends on its own
*published* `@netgrep/netgrep@^0.1.3` from 2022.

*Bonus:* extending `scripts/post_build.js` to copy the version out of `Cargo.toml` closes backlog item 9 —
version drift between `Cargo.toml` and the JS manifest becomes structurally impossible rather than a thing to
remember.

### 5. Rust: three sub-crates, no fork

`packages/search/Cargo.toml` drops `grep = { git = "https://github.com/dgopsq/ripgrep", tag = "13.0.0-wasm" }`
for `grep-regex` + `grep-searcher` + `grep-matcher` from crates.io.

The reasoning, which took some digging to establish (see `docs/decisions/0001-fork-ripgrep-for-wasm.md`):

- `lib.rs` only ever uses those three crates.
- The fork exists solely to patch `grep-printer`, `ignore` and CLI-core — swapping `std::time` for the
  `instant` crate, because `Instant::now()` has no clock on `wasm32-unknown-unknown`.
- Those crates arrive **only** because `Cargo.toml` depends on the `grep` *meta-crate*. Depending on the three
  sub-crates directly means they are never compiled at all.

So the fork is not merely replaceable — the problem it solves stops existing. This also stops compiling a
filesystem walker and a terminal printer into a browser binary.

The upstream `grep` meta-crate (0.4.1, on crates.io since 2025-10) was rejected: it is a smaller diff but
keeps dragging in exactly the wasm-hostile crates the fork had to patch.

*Also in this decision:* `wasm-bindgen` 0.2.82 → 0.2.126 and `rust-toolchain.toml` → 1.97.1. These are one
atomic change, not three — 0.2.82 requires Rust ≤ 1.81 (Rust 1.82 changed the wasm C ABI), and current
`grep-matcher` requires edition 2024, i.e. Rust ≥ 1.85. Backlog item 4 called these mutually exclusive. They
are not; that deadlock was an artifact of the old pins, and both sides clear together. Verified — see
[Appendix A](#appendix-a-the-fork-removal-probe).

*Also:* remove `wee_alloc` (dead since 2019, known unfixed leak) and **report the `.wasm` size delta**.
Current binary is ~1.0 MB. Modern `rustc` may have closed the gap that justified it in 2022. Measure; do not
assume, in either direction.

*Open question for execution:* `memmap2` still compiles in via `grep-searcher`'s default features — dead
weight in a browser. Test `default-features = false`.

### 6. Toolchain only. The correctness bugs are not touched.

3a (chunk-boundary false negatives), 3b (poisoned partial cache) and 3c (panic on invalid regex) stay exactly
as they are, still documented in `BACKLOG.md`.

The reason is not timidity, it is *attribution*. The acceptance criterion for this work is **"behaviour after
is identical to behaviour before"**. That is only a meaningful claim if nothing is deliberately changing
behaviour at the same time. Mixing in bug fixes would make every behavioural difference ambiguous.

Since nothing is published, users are unaffected either way.

### 7. Vitest + Biome

Replaces **ten** packages with **two**:

| out | in |
|---|---|
| `jest`, `ts-jest`, `babel-jest`, `jest-environment-jsdom`, `@types/jest` | `vitest` |
| `eslint`, `eslint-config-prettier`, `@typescript-eslint/parser`, `@typescript-eslint/eslint-plugin`, `prettier` | `@biomejs/biome` |

Both configs are rewritten from scratch regardless of choice, because both are Nx boilerplate that dies with
Nx. Worth stating how little is being lost: **the only hand-written ESLint rule in the entire repository is
`no-console: "warn"`.** Everything else is `@nrwl/nx` plugin configuration. And
`packages/netgrep/jest.config.js` is a `jest.preset.js` reference plus a `globals: {'ts-jest': ...}` block
that ts-jest 29 has already deprecated.

Vitest additionally removes a standing tax: `@netgrep/netgrep` is ESM-only (`"type": "module"`, `.js`
extensions on relative imports), and jest's ESM support remains the painful path.

*Accepted cost:* Biome's formatter differs from Prettier in edge cases. Expect one whole-repo reformat commit,
kept separate so it does not pollute a review.

### 8. TypeScript 7.0.2, in one jump

`npm i typescript` now installs 7.0.2 — the Go rewrite is the `latest` tag, not a preview.

The compatibility surface here is genuinely small: ~380 lines, no decorators in use, no namespaces, no exotic
types. And `tsc` is only load-bearing for the `dist` build and typecheck — vitest transforms via esbuild and
Biome has its own parser, so neither depends on the compiler.

*Also in this decision*, the tsconfigs shed their Nx boilerplate:

| current | change to | why |
|---|---|---|
| `experimentalDecorators`, `emitDecoratorMetadata` | delete | nothing uses decorators |
| `target: "es2015"` | `es2022` | 2015 for a library shipping in 2026 |
| `lib: ["es2017", "dom"]` | `["es2022", "dom", "dom.iterable"]` | streams, async iteration |
| `moduleResolution: "node"` | `"bundler"` (or `nodenext`) | legacy resolver, paired with ESM output |

`tsconfig.spec.json` also has a trailing comma — valid JSONC, but it goes.

### 9. Pin exact; the files are the source of truth

`rust-toolchain.toml` = `"1.97.1"`, `.node-version` = 24.x LTS, and a `packageManager` field pinning pnpm via
corepack. **CI reads those files rather than restating versions** — today all three workflows independently
hardcode `'18.7.0'` and `toolchain: stable`, which is how local and CI drifted apart.

This is the direct fix for the root cause of P0 item 1. A floating `stable` channel meant an unrelated Rust
release broke the build with no commit to point at.

*Rejected:* a Node 20/22/24 CI matrix. The shipped artifact is a browser-targeted ESM library; the Node
version only ever affects build tooling.

### 10. `packages/example` → Vite, wired to workspace source

156 lines of plain JavaScript behind its own 2,284-line lockfile, served by webpack + webpack-cli +
webpack-dev-server + html-webpack-plugin. Four dependencies become one; the lockfile disappears into the
workspace.

More importantly, combined with decision 4 it finally runs against **local source** rather than the 2022
published packages — which matters most precisely now, during a migration whose whole acceptance criterion is
"behaviour is identical".

*This softens an `AGENTS.md` hard rule.* "The example app is a demo, not a test" was true because it silently
tested stale published code. Post-migration it is still not an automated test, but it is no longer lying. The
rule needs rewording in PR 5, not deletion.

*Note for execution:* wasm-pack's bundler target needs `vite-plugin-wasm` (+ top-level-await) under Vite. The
alternative — switching to `--target web` — changes the published artifact, so it is out of scope under
decision 1.

### 11. Modernize the workflows; no dependency bot

All three workflows: `actions/checkout@v2` → `@v4`, the **archived** `actions-rs/toolchain` →
`dtolnay/rust-toolchain`, Nx commands → pnpm scripts, and a version-pinned ChromeDriver (backlog item 2 —
`wasm-pack test --chrome --headless` fetches the *latest* driver, which cannot drive an older installed
Chrome; observed as ChromeDriver 151 against Chrome 150 → `invalid session id`).

No Renovate, no Dependabot. On a repo maintained in bursts, per-dependency PRs become noise that gets ignored,
which is worse than deliberate periodic review. Revisit if the pinned versions start feeling stale.

The two publish workflows are fixed but stay dormant — they fire on `search-**` / `netgrep-**` tag pushes,
and no tag is being pushed.

### 12. An integration test over the real WASM, written first

`Netgrep.spec.ts` mocks **both** `fetch` and `@netgrep/search`. So the 7 TypeScript tests never touch the
engine, the 2 Rust tests never touch the streaming layer, and nothing in CI can currently substantiate
"behaviour is identical" across a 44-minor-version `wasm-bindgen` jump.

The test drives real `search_bytes` through the real `Netgrep` streaming loop, feeding a hand-built
`ReadableStream` from fixture bytes — no network, deterministic chunking, which also makes it the right place
to pin chunk-boundary behaviour.

**It is written first, in PR 1, against the current stack.** A baseline written after the migration would only
describe where things ended up.

It will encode bug 3a as *documented current behaviour*, with a comment pointing at `BACKLOG.md`. That reads
wrong at first glance and is correct: under decision 6 the test's job is to detect unintended change, not to
assert desired behaviour. When 3a is eventually fixed, the test changes in that PR — visibly, which is the
point.

Closes backlog item 3d.

### 13. Five PRs

Each must leave `main` green. Sequence and contents in [The PRs](#the-prs).

### 14. Working agreement

- Plan doc first (this file), then PR 1, then **stop for review** before PR 2. Repeat.
- Free push to any branch **except `main` / `master`**.
- Version bumps, `git tag` and publishing remain **human-only**. Unchanged from `AGENTS.md` §6.
- The ripgrep fork is never edited from this repo. After PR 3 it is unreferenced; whether to archive
  `dgopsq/ripgrep` is the maintainer's call.

## The PRs

### PR 1 — Green baseline + safety net

*Nothing is modernized here. This PR exists to create a trustworthy before-picture.*

- Pin `rust-toolchain.toml` to `1.81.0` and pin the same in CI → **CI goes green for the first time**.
- Add the integration test (decision 12), running real WASM through the real streaming loop.

**Acceptance:** CI green on `main`. Integration test passes against `wasm-bindgen 0.2.82` and the forked
`grep`. Its output is recorded in the PR body as the reference behaviour.

*Wrinkle, as resolved:* linking real WASM into the test needs local resolution, which decision 4 does not
deliver until PR 2. Rather than a `moduleNameMapper`, the test uses `jest.mock('@netgrep/search', () =>
require(...))` returning the **real** module — the mock hook used to install the genuine implementation. It
loads `packages/search/pkg-node/`, a second wasm-pack output built with `--target nodejs`, because the
published `pkg/` uses the bundler target whose `import * as wasm from './index_bg.wasm'` Node cannot resolve.
Same Rust, same release profile, same `.wasm`; only the module-loading preamble differs. Added as an
`nx build-node search` target and a CI step; both disappear into pnpm scripts in PR 2.

*Findings:* the baseline surfaced **two previously unknown correctness bugs**, now recorded as backlog 3e
(`^` anchors to the chunk, not the line, for case-sensitive patterns — a verified one-line fix) and 3f (a
single NUL byte discards the entire chunk). Both are pinned as tests asserting current behaviour, not fixed,
per decision 6.

### PR 2 — JS toolchain

- Remove Nx and `@nxrs/cargo` (9 packages); delete `nx.json`, `jest.config.ts`, `jest.preset.js`, all
  `project.json` and `.eslintrc.json` files.
- pnpm workspaces; one lockfile replaces three; drop root's self-dependency on `@netgrep/netgrep@^0.1.3`.
- Add `packages/search/package.json` (decision 4); extend `post_build.js` to sync the version.
- Hand-write `packages/netgrep`'s published manifest, replacing what `@nrwl/js:tsc` synthesized.
- vitest + Biome replace jest/ts-jest/eslint/prettier; port the 7 unit tests.
- TypeScript 7 + tsconfig cleanup (decision 8).
- Root scripts: `build`, `test`, `lint`, `format`, `typecheck`.

**Acceptance:** every root script green. The PR 1 integration test passes **unchanged**. Reformat lands as a
separate commit.

### PR 3 — Rust

- Drop the fork → `grep-regex` 0.1.14 + `grep-searcher` 0.1.17 + `grep-matcher` 0.1.9.
- `wasm-bindgen` 0.2.82 → 0.2.126, `wasm-bindgen-test` 0.3.32 → 0.3.76.
- `rust-toolchain.toml` 1.81.0 → 1.97.1.
- Remove `wee_alloc`; test `default-features = false` on `grep-searcher`.

**Acceptance:** the PR 1 integration test passes **unchanged** — this is the load-bearing check of the whole
plan. `.wasm` size delta reported in the PR body against the ~1.0 MB baseline, `wee_alloc` removal isolated
enough to attribute.

*Outcome:* one assertion did change, and correctly so — the dependency move **fixed backlog 3e** (`^`
anchoring to the chunk instead of the line), so that test was inverted in the same PR, as its own comment
required. Everything else held.

Three findings: `[profile.release]` had never applied, because Cargo ignores it outside the workspace root —
so every release build to date was unoptimized; `wee_alloc` turned out to be worth only 0.6%, vindicating
this item's "measure, do not assume"; and the binary still grew 10.6% net, driven by `regex-automata`'s
larger tables. Full accounting in [`../BACKLOG.md`](../BACKLOG.md) items 14 and 15.

### PR 4 — Example + CI

- webpack → Vite, wired to workspace source.
- All three workflows modernized (decision 11), reading pinned versions from files.

**Acceptance:** `pnpm dev` in the example searches a real URL against locally built WASM. All workflows green.

*Outcome: the Vite port failed and was reverted; the CI half shipped.* `vite dev` worked (67/67 fixtures
matched in real Chrome) but `vite build` silently emitted a bundle that never loads the wasm, on both Vite 8
and Vite 7. The example stays on webpack, which supports the bundler-target import natively. Full write-up in
[`../BACKLOG.md`](../BACKLOG.md) item 16 — including the consequence that matters more than the demo: **every
Vite consumer of the published package hits this**, which is a direct argument for revisiting decision 1 and
shipping a `--target web` build.

### PR 5 — Docs

- Rewrite `AGENTS.md`: §2's dev-loop gotcha is **deleted** (fixed in PR 2, and a stale warning about a
  non-existent trap is worse than none); §3 toolchain, §4 commands, §6 hard rules all updated.
- Rewrite `docs/ARCHITECTURE.md`; rewrite `docs/BACKLOG.md` (items 1, 2, 3d, 4, 5, 6, 7, 8, 9, 10 closed).
- Mark ADR **0001** (fork ripgrep) and **0008** (wee_alloc) as **Superseded**, with the reasoning preserved —
  they explain why the code looked the way it did, which stays valuable after the fact.
- Add ADRs for: removing Nx, pnpm workspaces, the wrapper-manifest shape, Vitest+Biome.
- Update `.claude/skills/wasm-release/SKILL.md` (every command in it changes) and `.claude/settings.json`.

**Acceptance:** every command in `AGENTS.md` executed and verified, exactly as when it was first written.

## Appendix A — the fork-removal probe

Run 2026-07-28. The real `packages/search/src/lib.rs`, unmodified except the three import paths and the
`#[global_allocator]` block, compiled against current dependencies:

```toml
wasm-bindgen  = "0.2.126"
grep-regex    = "0.1.14"
grep-searcher = "0.1.17"
grep-matcher  = "0.1.9"
```

```
$ cargo build --target wasm32-unknown-unknown
   Compiling grep-matcher v0.1.9
   Compiling grep-searcher v0.1.17
   Compiling grep-regex v0.1.14
   Compiling wasm-bindgen v0.2.126
   Compiling wasmprobe v0.0.0
    Finished `dev` profile [unoptimized + debuginfo] target(s) in 11.09s

$ rustc --version
rustc 1.97.1 (8bab26f4f 2026-07-14)
```

No fork, no `instant` crate, no edition-2024 conflict. This is the evidence for decision 5 and the reason
backlog item 4's "mutually exclusive" framing is withdrawn.

Incidental finding: `memmap2 v0.9.11` appears in the build via `grep-searcher`'s default features — dead code
in a browser binary, worth testing `default-features = false` in PR 3.

## What is deliberately not in this plan

Recorded so a future reader knows these were considered and rejected, not overlooked.

| | why not |
|---|---|
| Publishing 0.2.0 | Decision 1 — the goal is a healthy repo, not a release. **Worth revisiting:** backlog 16 shows the published artifact is unusable under Vite. |
| `exports` map; wasm-pack `--target web` | Consumer ergonomics; only pays off on release. |
| Fixing bugs 3a / 3b / 3c | Decision 6 — would destroy attribution during a large migration. |
| Node.js / Bun / Deno support | A feature. `fetch` + streams are now universal, so it is newly *possible* — worth its own conversation. |
| Returning match details instead of a boolean | A feature, and a breaking API change. |
| Renovate / Dependabot | Decision 11. |
| Node CI matrix | Decision 9. |
| Archiving `dgopsq/ripgrep` | Maintainer's call, after PR 3 lands. |
